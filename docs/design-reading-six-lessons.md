- 《项链》接入同一专题阅读器，增加请柬、首饰和遗失时点的导读，沿用历史英文原文及已有逐句翻译，不引入版权不明的中文译本。
- 《桃花源记》展示“记”的全文；原文路线、文言线索、渔人/村民按阅读进度可用，独立模拟路线不回填原著。
- 《劝学（节选）》完整展示既定四段选文，不冒充《劝学篇》全篇；明确选文范围，提供比喻—关系—结论、反例讨论与字词解释，无角色和分支。
- 《木兰诗》展示全诗，提供详略与留白导读、当前诗段的木兰视角和独立分支；不混入影视设定，不虚构作者。
- 中文作品不再显示英译中任务或“仅译文”导致正文消失的选择。古文解释通过安的伴读问题显式发起，不自动联网或生成。

当前交付是本地功能版与有限试读，不是原计划全部二十四条语义验收或每条新分支结局的模型验收。没有提交、推送、服务器部署或扩大导入入口。详情见 [六篇试用记录](evals/reading-six-lessons-results.md)。

## 2026-09-11 体验修正：完整原文优先

## 1. 产品选择

首批六篇：《孔乙己》《项链》《背影》《桃花源记》《劝学》（明确节选范围）、《木兰诗》。总目标二十篇，其余十四篇在六种体验验证之后再展开。

定位为「可互动的文学阅读专题」，可用于自主阅读和讲解展示。借鉴课件的编排，不默认引入课程、作业、考试、评分、学习排行与教学管理。不是所有篇目必须改写结局，不以对话次数衡量阅读价值。

共同价值：从原文出发，通过作者和时代背景理解作品，通过不同视角形成自己的解释。AI 的角色是回应读者，连接依据与问题；不是把预制卡片逐张念出来。

六篇分别设计页面信息层级和核心互动，但复用原文渲染、来源查看、伴读、缓存、名字存档和故事分支底座，不维护六套独立聊天/存档系统。

## 2. 公共页面能力

入口展示六张专题封面：篇名、一句阅读邀请、文体与可体验方式；不用「知识点1/2/3」作为首屏。旧五篇作品和已有存档仍可进入，不删除、不自动重新解释旧存档。

每篇包含以下内容，但可采用不同布局和顺序：

1. **进入作品**：有明确策划主题的首屏，直接读原文或开始核心互动；不强制先完成作者生平学习。
2. **原文**：清楚标明版本、语言、全文/节选、段落位置；保留字号、书签和笔记。外文译文与文言注释分开，不把现有英译中工具直接套到古文。
3. **写下它的人**：只精选与这篇文章相关的生平节点、其他表达及关系，不堆叠完整百科。不把作品叙述者自动当作者本人。
4. **作品之外**：作者生活时间、创作/发表时间、作品内叙事时间分开；不把创作背景直接赋予人物。编写前逐条核对来源，未知保留。
5. **该篇专属互动**：见六篇设计。人物、时代和文本中的空白必须有边界，不无限追问或强迫改写。
6. **带走一点东西**：自愿保存自己的理解卡、观点图或故事结局；不把每篇都包装成游戏通关，不给文学理解打唯一正确分数。

背景内容优先使用预先核对、可追溯的小型材料包。实时联网是主动扩展能力，不是展示路径的必要前置；搜索失败明确提示，不用无关网页冒充有效研究。

## 3. 六篇页面设计

### 3.1 孔乙己：咸亨酒店里的笑声

- **首屏与布局**：酒店空间示意、原文与人物视角并列；空间是编者示意，不伪装为历史复原图。
- **阅读主问题**：同一阵笑声，对不同的人意味着什么？
- **作者与背景材料任务**：核对作品创作/发表信息；挑选与人物处境相关的教育、身份与生计资料，不从作者经历直接推断人物动机。
- **核心互动**：固定同一段原文，在小伙计、掌柜与孔乙己之间切换，比较他们看见什么、关心什么、不知道什么。相同事实在不同视角下组织，而不是给三个人完全一样的全知提示。
- **可选分支**：选择一个明确原文时点，尝试不同的对待方式；只在新世界线发生，不承诺一次善意必然改变全部命运。
- **产物**：「同一阵笑声，三种处境」理解卡；产生分支时复用结局纪念卡。
- **边界用例**：原文未确认的结局不得写成确定史实；后续信息不进入早期人物视角。

### 3.2 项链：说出真相之前

- **首屏与布局**：舞会—遗失—选择的时间线，人物已知/未知信息按当前时点展开。首次进入不在卡片或背景中泄露结局。
- **阅读主问题**：体面、信任与恐惧如何影响一个选择？
- **作者与背景材料任务**：莫泊桑与该作品的创作背景、叙事与反讽相关材料，以及必要的社会背景；不预填未经核实的货币购买力或阶层细节。
- **核心互动**：读者在某一时点与人物谈论坦白，安解释双方当时各自掌握的信息；改写模式才允许把建议转成事件。
- **产物**：原著与新故事双时间线、真实参与回合关联与署名。
- **边界用例**：不能提前告诉不知道真相的人物首饰的真实价值；建议、计划、实际完成分开。寻找等日常过程可以概括，方向明确时收束。

### 3.3 背影：那一刻，与后来

- **首屏与布局**：原文细节与两条阅读轴——文中当时的感受、回望时的表达。优先放大具体动作和叙述变化。
- **阅读主问题**：经历同一件事的人，后来为什么会有不同的理解？
- **作者与背景材料任务**：核对文本中事件与写作时间、相关经历的可靠材料；区分作者自述、旁证和读者解释。
- **核心互动**：选择细节，查看文本如何从动作转到感情；与安比较两种可能的解释。人物视角若提供，只能是明确标识的文本演绎，不冒充真实朱自清或其父亲的未公开心声。
- **产物**：「当时没有看见，后来才理解」细节—理解卡；个人经历输入完全自愿，不要求披露家庭隐私。
- **边界用例**：不引导用户把父母行为一律合理化，不用「你应该感动」评价读者；默认不改写真实人生结局。

### 3.4 桃花源记：进去之后，是否还想回来

- **首屏与布局**：与原文段落对应的进入、停留、离开路线；标为作品空间示意，不当真实地理路线。
- **阅读主问题**：一个令人向往的世界，究竟隔绝了什么，又保留了什么？
- **作者与背景材料任务**：陶渊明相关经历、文本时代线索及不同解读的证据，不能把文学想象直接列为发生过的历史事件。
- **核心互动**：从渔人或村民当下可知的信息交流；安在场外解释文言与时代线索。读完后可以模拟留下、离开或讲述见闻带来的不同走向。
- **产物**：原文路线与模拟路线卡，以及未被原文回答的问题。
- **边界用例**：不宣称确定桃源真实位置；不得把模拟答案回填为原著留白的唯一解释。

### 3.5 劝学：一句话，怎样成为一个论证

- **首屏与布局**：原文与可展开的「比喻—要说明的关系—结论」图，不提供无意义的人物关系图。
- **阅读主问题**：这段话为什么能说服人，又在什么条件下值得追问？
- **作者与背景材料任务**：核对荀子、篇章与所用节选背景，区分该篇明确论述与思想史概括。
- **核心互动**：读者选择一个比喻，安指出对应原文和论证作用；读者可以提出反例或质疑，系统允许讨论解释的条件，不自动评为错误。
- **产物**：自己的论证地图或一条带依据的回应。此篇没有故事推进、影响力档位、世界线与结局按钮。
- **边界用例**：不把解释改写成古人原话；不由「作者可能回应」生成可引用的真实语录。

### 3.6 木兰诗：诗里写下的，与诗里省略的

- **首屏与布局**：按篇章展开的时间带，对比篇幅密度；展示哪些阶段详写、哪些略写。
- **阅读主问题**：为什么诗歌在某些瞬间停留，却把漫长岁月一笔带过？
- **作者与背景材料任务**：作品来源和流传背景，作者不明如实标记，不制造人物作者档案。注意文本线索与后世改编分开。
- **核心互动**：代入出征前、归来等原文节点，讨论身份、家庭、选择；对没有记载的战事、关系、私人体验，明确区分原文与想象。
- **产物**：详略与选择的理解卡；明确进入模拟模式后，可形成带标识的另一种结局。
- **边界用例**：不把影视改编人物和剧情当作诗歌原文，不编造确切历史人物生平。

## 4. 内容与证据契约

新增策划内容至少分为 `original` 原文、`context` 核验背景、`interpretation` 有限解读、`simulation` 模拟四层。

- 原文与背景引用带来源及定位。译本、节选和教材注释分别核对使用范围；不直接搬用不明来源的教材讲义。
- 作者、叙述者、人物是不同主体。诗歌或民歌作者不明不妨碍页面成立。
- 背景卡标明来源、信息类型和剧透范围；未读者不会被全书分析或作者卡提前泄露作品结局。
- 精选背景可预生成，但标记「已整理资料」，不播放假的实时搜索或分析动画。
- 模型实时回答展示实际依据和状态。没有发生的工具调用、角色干预和存档写入不得显示成功。
- 作者专题资料是该篇公共编辑内容，不从任何登录名字的私人作者档案中自动抽取或公开资料。
- 学习记录和个人输入继续按名字隔离；名字本身不构成可靠身份验证。Demo 不新增分享私人笔记功能。

## 5. 技术实现边界

策划数据建议采用 `ReadingLesson`：书籍/篇目 ID、文体、首页布局、策划主题、来源清单、作者/背景卡、原文锚点、互动节点、能力开关和结尾产物类型。

能力开关至少区分 `companion`、`character_perspective`、`story_branch`、`argument_exploration` 和 `text_annotation`。前端隐藏不适用入口，后端同样拒绝未开放能力，不仅靠提示词限制。

六个专题可拥有独立页面组件，但共用阅读器及服务；URL 保留 book ID，旧伴读与分支深链接兼容。作者专题背景资料与私人「作者工作台」职责分开，暂不改造为公共作者管理系统。

本轮不开发任意导入、OCR、任意书籍分类、通用知识图谱编译器、自动课程生成、考试题库、教学账号或学习效果排行。知识图与路线图是有原文依据的精选结构，不宣传为任意全文自动抽取。

## 6. 实施顺序与验收

1. **内容策划**：确定六篇原文版本、节选范围、作者/时代材料与引用；列出未核实项目，未核实内容不进入正式背景卡。
2. **两篇体验试样**：先做《孔乙己》的多视角和《背影》的细节/回望，验证独立页面确实改善体验，而不只是换颜色。复用已有《项链》，不重做已经可用的分支底座。
3. **其余四篇**：完善《项链》，补齐《桃花源记》《劝学》《木兰诗》，检验非故事型页没有不适用的操作。
4. **统一收口**：入口、原文和背景的跳转、名字存档、恢复、页面可读性及有限真实模型验收。
5. **是否扩到二十篇**：六篇主要路径都可用后再扩展；比赛部署另行确认，不在此处隐含授权。

每篇固定四条验收，共二十四条：

- 主路径：可以完成该篇专属互动并看到其有意义的输出，不强制反问或无穷延伸。
- 依据与来源：原文、背景、解读、模拟可区分，引用准确回到来源。
- 边界：覆盖各篇上文的专属边界；全知背景不污染人物、真实经历不被模拟改写。
- 保存与恢复：刷新后保留已保存成果；不跨名字访问、不覆盖旧存档；取消/失败不假报成功。

同时检查桌面与窄屏、键盘可达性、原文字号和对比度、旧五篇路径兼容。先运行不耗模型额度的结构与界面测试，再对明确的代表性路径做有界真实验收；记录成本，失败停止排查，不自动无限补跑。此设计阶段不触发模型批量生成。

成功标准不是「六篇都能聊天」，而是陌生体验者能说出：这篇原文中的哪个细节、哪个处境或哪种论证，因为这次互动而变得更清楚。

## 2026-09-11：首批两篇体验试样

已实现《孔乙己》《背影》的专题入口、完整原文、可追溯背景和理解卡：

- 《孔乙己》：同一段原文的三种立场提示，选择后将人物与段落带入既有伴读，用户确认发送；不是静态假聊天，也不会改变原著。
- 《背影》：三个细读片段和“那一刻 / 后来回望”切换。导读明确标注为一种解读；只与安讨论，不创建作者或父亲的角色，也不生成改写分支。
- 原文、预置资料、编者导读、AI 人物演绎分别标注。预置背景只提供给安，不进入人物上下文；本轮联网失败仍明确显示，不伪装为检索成功。
- 理解卡复用按名字、作品隔离的服务器手记，不另建账户或数据库。重启后可恢复；展示仍遵循原有阅读范围，收起后续段落不删除后续手记。
- 保留原五篇故事与既有记录；`mode=reader` 仍可进入常规伴读。《背影》的 `mode=story` 请求被前后端共同限制为只读。

本批仅是两篇试样，不代表六篇或二十篇已完成；其余四篇、批量内容制作和比赛部署仍按上文顺序推进。详细核验见 [首批专题验收](evals/reading-lessons-results.md)。
