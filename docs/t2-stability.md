# T2.6 稳定上线：开发契约

> 状态：已冻结，开始实施。T2.1–T2.5 的召回语义不再扩张；本轮负责证明它可以长期运行、可降级、成本可接受，并在达标后成为默认模式。

## 1. 要解决的问题

T2.1–T2.5 已经证明 Agent 能自主决定是否召回、核对正文、声明证据、组合六类来源并维护有限注意焦点，但证据仍来自受控虚构案例和少量重复运行。当前还不能回答：

1. 长时间重复运行时，行为是否漂移。
2. 单一来源、工具或模型循环失败时，回答是否仍可用且可解释。
3. 召回工具循环的 token 与延迟是否适合成为默认路径。
4. `agent` 是否已经具备替换 `legacy` 默认值的工程条件。

T2.6 不增加新的记忆来源、自动 ranker、向量检索、图扩散或隐藏注意算法。

## 2. 冻结决策

### 2.1 上线目标

- 所有验收门槛通过后，空 `RECALL_MODE` 默认解析为 `agent`。
- 显式 `RECALL_MODE=legacy` 永久保留为紧急回退开关。
- 默认切换必须是最后一个提交；任何门槛未达到时继续保持 `legacy` 默认。

### 2.2 降级语义

- 单一来源失败：标记该来源不可用，其他来源和一般回答继续工作。
- 搜索为空：视为正常结果，不回退最近 Episode。
- 搜索或读取失败：不把失败候选当证据，不伪造正文。
- Attention Workspace 不可用：退化为无跨回合注意的 Agent 模式。
- 达到最大步骤、超时或流中断：已有可见回答予以保留，并公开标记降级原因。
- 同一回合不静默切换 Legacy SideQuery；整体回退只由显式运行配置完成。

公开健康状态只记录组件、来源、结构化原因码和是否可恢复，不记录正文或隐藏推理。

### 2.3 会话状态

- Attention Workspace 和任务焦点继续只存在于进程内。
- 重启后不恢复旧中心或旧焦点；下一轮依据 STM、Workspace、Intent、Episode 重新建立。
- 这是产品语义，不作为持久化缺陷处理。

## 3. 总回归

建立一个版本化 T2 稳定性清单，从既有四套案例中选取 25–30 个核心案例，覆盖：

- 普通问题不召回。
- 明确历史回忆、空结果、歧义和当前表达优先。
- Workspace/Intent 延续、切换、联合处境和歧义确认。
- Bond、SceneNorm、Workspace、Intent、Proposal、Episode 的单源与组合使用。
- 高干扰、满槽替换、跨回合连续、闲置增长与读取归零。
- 单来源不可用、工具错误、最大步骤或流中断。
- 进程重启后会话注意状态自然消失并可重建。

统一执行器需要：

- 一条命令完成离线清单校验与结果汇总。
- `-live -repeat 10` 执行真实 Agent 长期复验。
- 原始回答只写入 Git 忽略的 `data/evals/`；仓库只提交不含回答正文的汇总。
- 基础设施异常与行为失败分开统计，不通过修改案例迁就结果。

## 4. 成本与延迟

T2.5 基线：

- 平均 14,457.8 token / 有效回合。
- 平均延迟 8.386 秒。
- P95 延迟 15.756 秒。
- 复杂多源阶段曾出现 P95 38.76 秒。

优化顺序：

1. 去除系统引导中的重复语义，保留所有证据边界。
2. 鼓励同类读取并行、同类公开声明合并，减少无意义模型循环。
3. 避免重复 list/read 和为了工具而工具。
4. 不以删除证据核验、公开声明或来源角色换取成本下降。

完成门槛：

- 硬性结构规则 100% 通过。
- 模型语义评分不低于 98%。
- 基础设施失败率低于 1%。
- 普通无需召回任务 P95 不超过 8 秒。
- 需要多源召回的任务 P95 不超过 20 秒。
- 平均 token 相比 T2.5 基线下降至少 20%，即不高于 11,566 token / 有效回合。

## 5. 可观测性

`TurnTrace` 增加结构化运行健康状态：

- `healthy`：本轮没有发现降级。
- `degraded`：本轮存在可恢复的来源、工具或模型问题，但仍有可用回答。
- `failed`：本轮无法形成可用回答。

原因码至少覆盖：

- `source_unavailable`
- `source_error`
- `search_error`
- `read_error`
- `attention_unavailable`
- `step_limit`
- `timeout`
- `stream_interrupted`

Room 实时流与历史 Trace 都显示公开健康状态；原始错误可以继续保留用于调试，但 UI 默认展示结构化摘要。

## 6. 交付顺序

1. 契约、稳定性清单和离线执行器。
2. 结构化降级状态、故障注入测试和 Room 展示。
3. Prompt 与工具轮次优化，记录优化前后成本。
4. 经授权运行纯虚构清单 10 次长期复验。
5. 门槛全部通过后切换 `agent` 默认值并保留 Legacy 回退测试。
6. 浏览器人工验收、全量测试、文档、提交，并在 T2 完全结束后统一 push。

## 7. 完成定义

只有同时满足以下条件才标记 T2 完成：

- 总回归和故障注入门槛全部通过。
- 成本与延迟达到冻结阈值。
- 默认 `agent`、显式 `legacy` 的配置测试通过。
- Room 能解释健康、降级、候选、读取、采用、排除和注意状态。
- 工作区干净，T2 全部提交一次性 push 到对应远端。
