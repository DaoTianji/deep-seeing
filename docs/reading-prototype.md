## 新版入口：先共读，再走进故事

- `/reading` 为书架；`/reading?book=necklace` 等书籍地址默认进入原文伴读，不创建故事分支。
- 原文按稳定段落定位，每页五段；点击段落编号确定讨论位置。字号、原文/译文对照、段落翻译、书签、手记和阅读完成状态均可使用。
- 可调整行距、收起桌面伴读栏；“人物与场景”抽屉仅显示当前已读证据覆盖的场景，顶部“读完之后”入口在小屏也可用，不要求翻到最后一页。
- 安与人物独立伴读；人物先由可见原文编译处境，不接收安的历史或研究。讨论位置、全书许可、文本版本和历史过滤共同约束上下文，语义防剧透仍需更多真实行为验证。
- 安可选择公开背景研究；独立书房已接入受控 World Gateway 与现有搜索提供者选择（`ROLE_SEARCH_PROVIDER` / `BRAVE_SEARCH_API_KEY`）。候选必须实际读取，再整理成背景卡，才能提供给回答。未配置认证搜索时覆盖能力有限，不保证每次有结果。
- 网络额度在 `data/reading-showcase/research/budget.json` 持久化，所有书籍和访客共享每天40次远程尝试；失败也消耗已预留额度。来源按访客隔离，正文文件收紧为0600。当前仍假设单实例运行。
- 伴读状态位于各书的 `<visitor>/companion/state.json`，不会写 Branch、导演事件、普通 Episode 或 Bond。翻译按正文版本、段落和风格复用；只有服务器提交回执才显示已保存。
- 回答前显示实际步骤，回答与依据核对完成后一次呈现，不是逐 token 输出。v10在每条新伴读记录下显示生成耗时、调用次数及网关返回的输入/输出/总Token；网关漏报或只返回部分字段时明确标记不完整，不估算。历史记录不补造用量。
- “最近一次请求”也显示失败请求的已发生调用、译文缓存/幂等重放的零调用回执；断线导致未收到回执时不能推断零用量。成功记录的生成统计随存档恢复，失败统计仅保留在当前页面，不额外持久化失败正文。用量不进入后续模型上下文，不等同账单金额。
- 点击“我已经读完了”后，可与安继续回望，或显式进入旧故事地图。`?mode=story` 和旧 `?branch=...` 链接兼容，分支页增加“回到原著伴读”。

## 作者工作台 · 2026-09-09

## 当前范围

这是 `codex/vibecoding-reading-showcase` 上的第一版垂直原型，不代表详细设计 S1–S5 全部完成。

- 独立书房界面：故事时间线、处境卡、人物视角、依据抽屉、对话和变化记录。
- 五篇**编者整理**的短篇场景与人物；人物可见范围由进入时点与角色共同决定。
- 安的阅读是真实模型调用：读取历史英文全文，逐场景形成公开解读，7 个检查点可恢复。不是伪造的进度动画。
- 每轮人物回应 → 安判断后果 → 独立连续性审核 → 原子保存。审核失败或模型超时不改变存档。
- 私聊只更新该角色；推进场景后，新的共同经历可更新实际在场人物。未来原著情节不随场景推进自动注入。
- 每个访客独立文件存档；分叉复制当前固定快照，不随父分支后续变化。Cookie 是本机原型存档凭据，不是账号系统。
- 原著片段可以定位到内置文本的 UTF-8 字节区间；中文说明是编者梗概，不冒充原文引语。

本轮还没有：任意书籍上传与自动世界编译、完整可交互知识图谱、Neo4j 索引、分支树导航、后台导演聊天、角色培养流水线复用、公开比赛部署和正式账号鉴权。右侧关系示意图为编者预置，不是模型自动抽取成果。

## 启动

在本分支工作区执行：

```sh
cd webui
npm ci
npm run build
cd ..
STORY_MODE=agent go run ./cmd/reading -env /absolute/path/to/model.env
```

访问 `http://127.0.0.1:3320/reading`。独立进程仅允许回环监听，不创建普通安的 App，不打开 Neo4j、Redis、Soul、Bond 或其他角色文件。

模型配置只使用 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`。不得提交配置文件。使用 `.env` 时仅选择自己的可信文件。

### DeepSeek 官方 V4 Pro

配置 `OPENAI_BASE_URL=https://api.deepseek.com`、`OPENAI_MODEL=deepseek-v4-pro`，Key 保留在本地 `.env`。以 `STORY_PROVIDER=gateway STORY_MODE=agent` 启动 `cmd/reading -env /absolute/path/to/.env`；不经过 Codex CLI，也不使用 Codex 订阅额度。

读书进程对 V4 系列显式开启 thinking、使用 low effort 和 8192 输出 token 上限，单次超时150秒。只返回最终 content，不保存 reasoning_content；截断回答返回错误，不交给故事写入流程。其他模型仍使用原有参数。配置变更需重启；根目录 `.env` 也会影响其他之后读取它的本地进程，服务器配置不随此改动。

小规模联网验证可运行 `DEEPSEEK_SMOKE_ENV=/absolute/path/to/.env go test ./internal/memory -run '^TestDeepSeekLiveSmoke$' -v -count=1`。只发送一次虚构短消息，默认测试不联网；它验证接口与 JSON 回答，不代表多轮故事行为已经验收。

`STORY_MODE`：默认 off（浏览）；observe（可真实阅读，不可生成互动变化）；agent（互动原型）。普通 Room 可显式设置此开关接入同一路由，生产默认行为不变。

数据默认 `data/reading-showcase/`，可用 `-data` 独立指定；目录 0700，JSON 0600。浏览器清理 Cookie 后将无法直接恢复旧访客存档。当前不做跨设备账户同步和加密落盘。

## 体验顺序

### 书架、记录与署名

`/reading` 默认进入书架；点击实体书封进入对应作品，页面顶部可回到书架。书架展示当前访客各书最近50条故事元数据，可直接恢复进行中分支或打开完结卡。记录来自本地服务文件，不仅依赖 localStorage 的最后一条ID。

结局卡可自愿填写1–40字符的名字或笔名，成功后显示署名并写入下载的 Markdown。署名只是访客标识，不是身份认证或原著作者；首次确认后不可覆盖，重复提交同名幂等。署名保存在 Branch 的读者元数据，不更改结局正文、故事版本或人物记忆；从结局分叉清除署名。

新增 `GET /api/story/records?book=...` 与 `POST /api/story/branches/{id}/signature?book=...`（name、revision）。书目接口包含当前访客的记录及阅读状态，使用 no-store；访客隔离继续由 HttpOnly Cookie 和目录共同限定。未实现账号或跨设备同步，清除 Cookie 后不能自行找回旧访客记录。

先在左侧“选择短篇”切换作品。旧地址默认《项链》，原有存档保持原路径；新书使用 `?book=magi|leaf|paw|kong`，每本书分别保存阅读进度、分支和浏览器恢复键。切换书籍不会触发模型调用，AI 阅读仍需主动点击。

| 作品 | 场景 | 建议进入点 | 核心边界 |
|---|---:|---|---|
| 项链 | 7 | 空了的颈间 | 夫妻不知道首饰真实价值 |
| 麦琪的礼物 | 6 | 一美元八十七美分 | 卖发、卖表及礼物不自动互相公开 |
| 最后一片叶子 | 7 | 倒数的叶子 | 信念不等于病理事实，关怀不保证治愈 |
| 猴爪 | 7 | 从火中捡回 | 咒语是听闻，门外身份和第三愿望保持原文留白 |
| 孔乙己 | 7 | 茴字的写法 | 流言不同于目击，不把结尾推测写成死亡确证 |

以下体验路径以《项链》为例，五本书均可对话、推进、手动完结与分叉。

1. 打开“故事地图”，默认到“空了的颈间”。
2. 点线索核对编者解释与历史原文；后续情节默认折叠。
3. “安的解读”中启动真实阅读，逐场景查看已完成结果。
4. 走进场景，与玛蒂尔德谈论坦白；查看新增听闻、判断、打算。
5. 继续下一场景：安围绕核心冲突推进，可以概括日常寻找与等待；方向明确时自动收束，不逐项派发无穷支线。
6. 切换当前在场人物，检查不同记忆；从此处分叉并尝试其他选择。
7. 刷新或重启后，通过“恢复上次存档”继续。

人物文本通过完整审核后显示，因此不是逐 token 流式回答。通常需要两至三次模型调用；网关超时会明确报错并保留上一版本，重试使用请求 ID 防止重复提交。

## 完结与来访者影响力

- 人物不再被要求每轮反问，简单确认可以简短回答。
- 核心矛盾已解决或选择足以形成明确走向时，导演可以自动提交结局。允许带遗憾的开放结尾，不必找回每件物品或修复所有关系。
- “让故事走向结局”显式要求收束：按照当前方向压缩执行过程，生成闭幕场景与完整纪念卡。不能以未执行的打算冒充成功，也不能为了完结伪造赔款、找回项链等结果。
- 纪念卡包含完整短篇回顾、收束原因、原著完整故事线（含结局）、本次故事线、关联真实来访回合的参与影响。可下载 Markdown 留存。
- `Branch.ending` 与本轮变化原子保存。已完结分支拒绝后续写入；历史可展开回看，另开分支不覆盖原卡片。重复结束请求幂等。
- 旧存档没有 ending 时继续保持进行中，不被启动过程强制完结。
- 影响力采用整数 **5–10**：5 保持原有自主性，6–9 逐步增加接纳建议与采取行动的倾向，10 为最高说服力；既传入 Actor 也传入导演。它不赋予额外知识、物品或资金，不突破私聊隔离和历史边界。
- 配置在下一次成功对话/推进/结束时保存，失败不改变存档；旧存档默认5。该配置是软性语义引导，不保证每次说服成功或跨模型效果严格单调。
- 对话区改为页面单层滚动，避免固定高度的内部滚动区域裁切长历史。

额外测试覆盖自动/手动完结、结局完整性与贡献引用、审核拒绝无部分写入、40轮上限后的手动收尾、已完结锁定、重启恢复、分叉与影响力真实注入。前端现在共10条测试。

可选的真实模型小规模检查（会使用当前网关额度）：

```sh
node scripts/check-reading-ending.mjs
```
