# 伴读：持久化逐句译本

英文书籍正文上方新增「全书逐句翻译」。点击后切换为对照阅读，按批生成全书中文译文；每句原文下面显示对应译文。首次消耗现有模型额度，不使用搜索服务或新模型。不会自动为所有书籍翻译。

- 每批最多 16 个句段、约 6,000 个原文 Unicode 字符；共用认知队列，每批后释放。单个超长句超过 8,000 字符时明确报错，不静默截断。
- 每批校验所有句子 ID、一一对应、非空与去重后原子保存。失败只保留已经确认的批次，不无限重试。
- 页面保持打开时逐批继续；暂停、离开页面或关闭浏览器会停止请求。重新打开点击「继续翻译全书」从存档续译，不是后台常驻任务。
- 刷新、翻页、查看完整译本只读存档，不调用模型。若响应丢失但批次已提交，旧 checkpoint 请求直接返回存档，不重复生成。
- 原文及字节锚点不变，阅读位置、全书剧透开关、聊天、笔记和故事分支均不写入。只展示当前页的译文。
- 通顺 / 贴近原文各自一份；沿用现有翻译风格选择。旧的「翻译这段」与段落译文继续兼容。
- 孔乙己为中文原文，不展示全书英译中入口。

## 存储与接口

文件：`<book-root>/<reader-id>/translations/<text-hash>-sentences-v1-zh-<style>.json`。目录 0700、文件 0600；按名字对应的内部 reader ID 隔离，与其他阅读记录采用同一访问规则。名字不是密码，同名可恢复同一记录。

存档含原文版本、分句算法版本、风格、目标语言、句子 ID / 段落 / 原文字节位置、原文、译文、已完成数量、生成模型和更新时间。文本变化生成新译本，不覆盖旧文件；损坏存档报错而不是重新计费覆盖。换模型不会自动重译已有内容，续译会使用当前配置的模型。

- `GET /api/story/companion/translation?book=necklace&style=fluent`：读取当前译本或未生成的分句骨架，无模型调用。
- `POST /api/story/companion/translation?book=necklace`，JSON `{"style":"fluent","completed":0}`：从指定 checkpoint 生成下一批。
- 全部接口要求现有名字会话 cookie 和 `X-Reading-Profile`，由服务端解析 owner，不接受客户端指定 owner。

## 边界与测试

分句是保守的英文标点切分，处理常见称谓、缩写、数字及引语；复杂缩写或引语可能保留为较长句段，不声称具有人工编辑精度。所有原文字节保持完整。AI 辅助译文可能有误，不是专业审定译本。

单测覆盖全库原文字节重建、句子锚点、批次 ID 校验、断点重开、请求重放、取消和失败恢复、名字 / 书籍 / 风格隔离、正文版本变化与中文书限制。前端测试覆盖主动生成、缓存重开、逐句展示、失败续译及暂停。测试使用受控模拟译文，不批量调用真实模型。
