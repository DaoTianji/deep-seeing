# T2：自主召回与证据闭环行为评估

> 目标：验证主 Agent 能否自主决定是否搜索过去，并让实际影响回答的历史形成“候选 → 读取 → 采用/排除”的公开证据链。候选排序、外围注意和多源召回仍不在本轮评估范围。

机器可读的长期案例源位于 `evals/t2/recall_cases.json`。本文解释评估原则和运行方式，不再作为需要人工复制的案例数据源。

## 运行方式

快速校验案例格式和数量，不调用模型：

```bash
go run ./cmd/eval-recall
```

运行一个真实 Agent 案例；每条案例使用独立的临时 Episode 存储和全新 STM：

```bash
go run ./cmd/eval-recall -live -case E1
```

`-live` 会把案例的测试问题和虚构记忆夹具发送给当前 `OPENAI_BASE_URL` 配置的模型服务。运行前必须确认该目的地允许接收这些评估数据；执行器不会读取或复制正式 Episode 存储。

完整运行三次并使用语义评分器，将逐轮证据保存为 JSONL：

```bash
go run ./cmd/eval-recall -live -repeat 3 -judge model \
  -out data/evals/t2-agent-recall.jsonl
```

还可以通过 `-category no_recall` 只运行一类案例。真实评估固定使用 `agent` 模式；`legacy` 的 SideQuery 基线由现有确定性回归测试保护，不与自主工具调用共用“是否搜索”的判定口径。

每一轮固定：

1. 从案例中的 `memory` 创建隔离的 Episode 沙箱，逻辑 key 稳定，物理 Episode ID 可变化。
2. 使用新的 Session 和内存 STM，上一条案例不会污染下一条。
3. 记录公开可观察的搜索、候选、读取、证据声明、工具调用、回答、错误、耗时和 token，不记录隐藏思维过程。
4. 先运行确定性规则，再按需使用模型依据固定 rubric 判断语义；不比较整段回答文本。

JSONL 报告逐轮保存时间、suite 名称、schema 版本、类别、模型、评分方式和公开观察证据，因此不同日期的结果不会失去归因信息。

## 两层判定

结构规则完全确定，适合像单元测试一样随代码运行：

- `required` 必须发生 Episode 搜索；`forbidden` 不得搜索；`optional` 允许 Agent 自主决定。
- 必须命中或不得命中的记忆使用稳定 fixture key 表达，不绑定随机 Episode ID。
- E1–E4、C1–C2 的目标夹具必须依次成为候选、被读取并声明为 `used`；只搜索到但未采用不能作为回答依据。
- `used` 必须属于本轮成功读取的候选；`dismissed` 必须属于本轮候选，并带固定原因码。未声明候选保持 `unknown`。
- 所有搜索为空时，不允许出现“最近 Episode”回退候选。
- Turn 错误直接失败。

语义规则检查长期行为边界：是否伪造过去、是否区分证据与概括、是否让用户当前表达优先、是否把状态观察扩大成诊断。它不要求固定措辞，也不限制搜索词、重试次数或工具路径。

## 结果与门槛

| 模式 | 普通任务无搜索 | 明确回忆有搜索 | 空结果无最近条回退 | 当前表达优先 | 备注 |
|---|---:|---:|---:|---:|---|
| legacy | 不适用：固定 SideQuery 16/16 执行 | 不适用：固定 SideQuery 16/16 执行 | 否 | 待人工评估 | 代码机制基线 |
| agent | 由隔离案例运行 | 由隔离案例运行 | 由隔离案例运行 | 由语义 rubric 运行 | 可重复多轮统计 |

通过门槛按三次重复计算：N1–N4 为 12/12 不搜索；E1–E4 为 12/12 命中、读取并采用目标夹具；A1–A4 为 12/12 不伪造，引用过去时必须有 `used` 证据；C1–C2 必须读取并采用目标证据；C3 为 3/3 当前明确要求优先；C4 为 3/3 空结果不回退并先询问主题。未达到门槛时只调整召回引导、候选卡或工具描述，不进入 Recall Broker 开发。

单次通过不代表稳定。正式比较至少运行三次，分别报告总体成功率和四个类别的成功率；延迟、搜索次数、候选数量和 token 只记录，不在本轮设置成本门槛。2026-08-26 的基线与证据闭环结果见 [t2-agent-recall-results.md](./t2-agent-recall-results.md)。

## 长期维护规则

- 核心案例只描述用户意图和不可违反的行为原则，不写死搜索词、调用次数、候选数量或回答原文。
- 真实使用中出现新的失败，先最小化并匿名化，再加入回归案例；修复前后的失败证据保存在评估报告，不塞进案例断言。
- 架构调整时可以提高 `schema_version`，旧报告继续保留其原版本，避免同名案例悄悄改变意义。
- 修改案例的语义规则必须经过人工审查；模型不得自行放宽通过门槛。
