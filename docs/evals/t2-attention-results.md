# T2.5 注意与竞争：行为验收结果

> 结论：T2.5 工程、确定性测试与真实 Agent 行为验收完成。9 类案例各重复 3 次，共 48/48 个有效回合通过结构规则和模型语义评分。

## 1. 验收范围

机器可读套件为 `evals/t2/attention_cases.json`，全部使用虚构数据，运行时为每个案例创建隔离 Episode、SceneNorm、Proposal、Workspace、Intent、Bond、STM 和 Attention Workspace。同一案例的连续回合共享同一个 session，以验证真正的跨回合状态。

覆盖：

1. 普通单轮任务不污染注意工作区。
2. 中心项目跨无关插曲保持并可恢复。
3. 当前任务进入中心，未来辅助计划进入支撑。
4. 未读取 Proposal 最多进入外围，不能成为事实或中心。
5. 中心满载时必须公开指定替换项。
6. 用户显式切换时，新任务优先，旧任务不继续主导。
7. 20 个以上跨来源干扰项中不逐条读取。
8. `idle_turns` 精确按 1→2→3 增长，成功读取后归零，不自动淘汰。
9. 当前明确表达与旧 Episode 冲突时，旧内容必须读取并排除，不能作为回答依据。

## 3. 基线后发现并修复的问题

第一版 8 类、15 Turn 基线为 45/45，但完成审计发现两处证据不足，因此没有直接宣布完成：

1. 报告只记录层级，没有硬性验证 `idle_turns`；同时读取项目不会重置闲置计数。最终实现增加自动 touch：成功 read 或公开 use 会归零，且评估逐回合验证 1、2、3、0；Trace 同时保存回合开始与结束快照，使这一变化可被历史回放。
2. 契约要求当前表达优先于旧 Episode，但旧套件没有冲突案例。最终增加虚构旧“只要一句话”偏好与当前“详细解释”冲突案例，硬性要求 search、read、dismissed、不得 used，并由语义评分验证当前要求获胜。

测试中还修正了两个评估器问题：

- Runtime 的公开软中断此前没有传递给执行器，导致截断回答被误判成行为失败；现在基础设施失败单列，每个案例最多重试 3 次。
- Intent 的 `due_at` 由隔离运行器生成但不写在夹具里；评分器现在允许回答引用 `read_intent` 实际返回的日期，避免把真实工具输出判成幻觉。

冲突案例不规定旧 Episode 必须永久保留或移出中心。Agent 可以保留、降级或删除它；真正的门槛是本轮公开排除且不能用于回答。这保持了“系统约束证据边界，语义路径由 Agent 自主决定”的原则。

## 5. 结论与下一步

T2.5 已证明：有限会话槽位、公开生命周期和 Agent 自主决策可以在当前模型上稳定工作，不需要先引入 Recall Broker、统一黑箱 ranker、向量搜索或图扩散。

下一步是 T2.6 稳定上线：长期回归、成本与延迟优化、降级策略，并评估是否将 `RECALL_MODE=agent` 设为默认值。在 T2 完全结束前不 push。
