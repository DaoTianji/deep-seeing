# T2.6 稳定性与分段性能结果

> 日期：2026-08-28。所有真实 Agent 评估只使用仓库内纯虚构夹具；原始 JSONL 位于被 Git 忽略的 `data/evals/`，本文不保存回答正文。

## 1. 长期行为回归

长期回归覆盖 28 个案例、35 个连续 Turn，按 10 次重复汇总：

| 指标 | 结果 | 门槛 |
|---|---:|---:|
| 硬性结构规则 | 328/328 | 100% |
| 有效语义评分 | 268/268 | >= 98% |
| 基础设施异常 | 2，0.61% | < 1% |
| 平均 token / Turn | 11,176.6 | <= 11,566 |
| 普通回合 P95 | 3.91s | 观察项 |
| 记忆增强回合 P95 | 25.033s | 观察项 |

原先把 25.033s 作为“召回 P95”会混合 Episode 检索、模型多轮工具决策、多来源处境处理和最终答案生成。该数字仍保留用于观察，但不再代表存储检索速度，也不阻断 T2。

## 2. Episode 分段性能

在新增工具级计时后，使用 E1 与 C1 两个纯虚构案例各运行 5 次。语义评分关闭，只执行确定性行为规则和真实 Agent 链路：

~~~bash
go run ./cmd/eval-recall -live -judge rules -repeat 5 -case E1,C1 \
  -out data/evals/t2-recall-timing-v1.jsonl
~~~

| 指标 | P50 | P95 | 硬门槛 |
|---|---:|---:|---:|
| `search_episodes` 存储操作 | 0.267ms | 0.471ms | <= 100ms |
| `read_episode` 存储操作 | 0.153ms | 0.759ms | <= 50ms |
| 首次公开召回事件 | 2.419s | 3.419s | 观察项 |
| 证据声明就绪 | 6.937s | 7.639s | 观察项 |
| 完整回答 | 10.099s | 10.688s | 观察项 |

10/10 回合的确定性行为规则通过，未发生基础设施重试。样本数为 10，因此 P95 使用 nearest-rank 时等于该批次最大值。

## 3. 结论

- 当前本地 Episode 搜索和读取均为亚毫秒级，远低于冻结门槛；没有证据表明存储检索是慢点。
- 召回链路的大部分时间发生在模型决定搜索、选择候选、读取后判断证据以及生成最终回答。
- `TurnTrace`、Room 实时事件和历史回放现在都会公开显示工具耗时及本轮相对时间；不记录 Episode 正文或隐藏思维。
- 后续优化应关注重复模型轮次与无意义工具调用，而不是为了端到端秒数删除证据核验。
