## 执行

- 使用当前生产 EpisodeRetriever/HindsightClient 和搜索、读取、证据声明工具；中性 benchmark persona，不注入安的身份。
- 每题独立 bank、文件、内存 STM；不构造生产 App，不调用 PostTurn/Review/Dream。
- 每段原始历史保留为一条 Episode，Hindsight 使用生产相同的提取、嵌入和重排配置。
- 每次远端写入前保存 uncertain 标记，成功后保存 indexed；不自动重试不确定写入。
- 完成题目结果独立持久化；索引保留，断点恢复不会重建已成功索引。
- 回答模型 DeepSeek V4 Pro high reasoning，单次输出最多 8192 token、最多 16 Agent 步、答题总超时 4 分钟。
- 第一题尚未答题时，将仅测试服务 LLM 并发从 1 提高到 4。操作者没有核实上游默认仅 5 秒的退出等待，导致第 14 条在途写入取消并返回 HTTP 500。13 条成功索引及预算保留；数据库审计确认被取消的文档、事实和片段均无残留（事务已回滚，无需删除），再允许一次有审计记录的显式技术恢复。不是答错后重跑，也不重置预算；初始耗时含维护，不能作为稳定吞吐基准。
- 若实际搜索回退到 BM25，标为无效 Hindsight 测试，不计作新后端成功。
- 官方分类评分提示不变，裁判使用 V4 Pro nonthinking，temperature=0、max_tokens=16；不是官方 GPT-4o 快照等价协议。
- 评分器与生成进程分离，已判定或不确定的评分都不自动重试。

- 独立 PostgreSQL 数据库/用户 hindsight_eval50，位于本项目新增的 memory-pg 容器中，不修改生产数据库。

## 本轮观测注意事项

- 首题应用 Trace 的 token 累计值与预算代理的最终供应商回执显著不一致。现有流式统计逐块相加，存在累计用量被重复计算的风险；本轮费用仅以独立代理账本为依据，不使用 Trace token 估价。不在运行中修改被测 Runtime。
- 第二题两次召回均在约 15 秒后记录 `hindsight_unavailable` 并回退 BM25，结果标记 `non-Hindsight retrieval invalidates pilot`。该题是本轮端到端失败，不从总样本中隐藏；也不得将其回退结果计为 Hindsight 的语义表现。当前证据仅确定触发客户端超时，不能据此断言是向量、数据库、图扩展或重排中的哪一步慢。
- 测试服务持续运行期间，`summary.json` 可能仍是之前技术中断时的旧快照。必须结合 runner/收尾服务状态、文件时间及逐题结果判断，不能把旧快照当作本轮最终汇总。
