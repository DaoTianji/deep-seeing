# 名字书房：轻量登录与记录隔离

2026-09-09 · 比赛分支，本地版本。不是密码账号系统，不改变远端部署或数据库。

## 使用

1. 打开 `/reading`，输入名字或独特笔名即可进入，不用注册、密码、邮箱或验证码。
2. 同一名字对应同一份书房记录。首尾空格忽略，英文大小写不区分；首次输入的显示名字保留。
3. 顶部可以退出或换名字。退出不删除记录；在连接**同一后端服务和数据目录**的设备上输入同名即可恢复。不同电脑各自运行的localhost不是同一个后端，不会凭名字自动同步。
4. 原有匿名数据保留。若浏览器仍持有旧访客Cookie且存在未归属记录，登录页提供可选的“把旧记录归到这个新名字”。默认不勾选；只允许归入新名字，不合并已有名字、不覆盖旧正文。

**名字不是身份验证。** 不同名字之间不能通过书架列表、猜分支ID或普通接口看到别人的记录，但知道某个名字的人可以主动登录同名。请用独特笔名，不存敏感资料；不要把这一版当作适合公开陌生人访问的安全账号系统。

## 隔离范围

- 伴读对话、阅读进度、书签和手记。
- 五本书的分支、人物在该分支的经历、结局和署名。
- 作者工作台、上传资料、作者认识和创作稿。
- 后台研究来源仍位于对应内部读者ID目录，不公开读者列表。

原著和编者书目是共享公共内容。每日搜索预算仍为服务级，不因切名字重置。模型配置和用量计费未改变，登录、退出和查会话不调用模型。

## 实现边界

- `data/reading-showcase/readers/index.json` 保存名字到随机UUID的映射和会话；目录0700、文件0600，未加密。
- 名字不用于目录拼接；限制1–40个Unicode字符，拒绝控制符和不可见格式字符。
- Cookie保存随机会话凭据，HttpOnly、SameSite=Strict，直接HTTPS时Secure；30天有效。服务器只持久化凭据哈希。退出使当前凭据失效，其他设备自己的会话不受影响。
- 所有公开 `/api/story/` 业务路由先解析会话，在请求context中指定内部owner。旧匿名Cookie不能绕过登录。
- 浏览器发送 `X-Reading-Profile` 与当前显示名字绑定。若别的标签页切换了名字，旧请求被拒绝，不能因共享Cookie而误写新名字的记录。
- 前端在会话确认前不挂载私有页面。切换名字卸载旧页面，最近分支缓存按读者ID分区；同源标签页通过storage事件刷新会话。
- 原有匿名记录选择归属时只关联现有UUID，不复制、删除或重写故事文件。旧Cookie丢失后不能凭空确定原匿名目录归谁，不会提供公开认领列表。
- 单服务实例文件存储；不支持多个进程并发写同一名字索引。备份需包含新的 `readers/` 目录和原有全部读者数据。

## 接口

- `GET /api/story/session`：当前名字或null，以及是否可以归属本浏览器旧记录；不返回其他名字。
- `POST /api/story/session`：`{"name":"笔名","claim_legacy":false}`，创建或恢复名字空间并设置会话Cookie。
- `POST /api/story/session/logout`：`{}`，退出当前会话。
- 其他 `/api/story/` 请求需Cookie及 `X-Reading-Profile: <session返回的reader.id>`。无会话401，名字不匹配409，别人的资源404。
- 原接口请求正文与数据结构不变，但匿名HTTP访问不再兼容；已有测试脚本已补名字登录。内部引擎测试保持直接调用，不触发模型。

## 验证结果

- Go全量及story/room Race通过。
- 前端45条测试、TypeScript检查和生产构建通过。
- 后端新增覆盖：未登录拒绝、不同名字列表与直接ID隔离、旧Cookie不可越权、同名跨会话及重启恢复、退出/到期、旧标签页串写拦截、输入校验、索引损坏拒绝访问、文件权限、并发同名、跨站登录拒绝、旧记录显式归属且不覆盖。
- 页面测试覆盖：登录前不加载私有页、仅输入名字登录、失败不假报成功、旧记录默认不归属、退出清空内容和旧链接、跨标签页切换及缓存分区。
- 在3323临时隔离服务实际用“登录验收甲”保存虚构手记，退出后“登录验收乙”看不到；重新用甲进入，原手记恢复。页面无控制台错误。隔离服务未加载模型密钥，用户现有匿名记录未被归属或修改。

本轮没有真实模型调用，没有提交、推送或部署远端。
